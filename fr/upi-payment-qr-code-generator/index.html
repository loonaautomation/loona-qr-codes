À propos de ce code QR Paiement UPI

Un QR UPI utilise le format standard upi://pay avec votre identifiant UPI, votre nom et un montant facultatif, pour que n’importe quelle application UPI puisse vous payer instantanément.

Un étal de thé affiche un QR UPI ; les clients scannent avec n’importe quelle application UPI et paient le montant exact. C’est exactement le problème que résout un code QR Paiement UPI : il supprime la saisie, la recherche et les erreurs, et les remplace par un seul scan d’environ deux secondes. Sur Loona, le code est généré localement dans votre navigateur comme un QR statique, ce qui signifie que les données vivent dans le motif lui-même. Il n’y a aucun serveur Loona au milieu, aucun lien court qui puisse être désactivé, et aucune période d’essai après laquelle vos documents imprimés cesseraient de fonctionner — un problème fréquent et coûteux sur de nombreux sites de codes QR dits gratuits.

Comment ça fonctionne

Ce générateur gratuit de code QR UPI construit le lien de paiement UPI standard et stocke ce lien dans le code QR en texte brut. Le lien commence toujours par votre identifiant UPI (VPA) et suit cette structure :

upi://pay?pa=YOUR-VPA&pn=YOUR+NAME&am=AMOUNT&cu=INR&tn=NOTE

Ici pa est le VPA du bénéficiaire (la seule partie requise), pn est le nom du bénéficiaire, am est un montant fixe et tn est une note de paiement — ces trois n’apparaissent que si vous remplissez ces champs — et cu=INR (la devise) est ajoutée automatiquement. Comme chaque application UPI lit le même lien standard, un seul code imprimé fonctionne avec BHIM, Google Pay, PhonePe, Paytm et les applications UPI bancaires. Le lien est créé dans votre navigateur ; Loona ne voit ni ne touche jamais vos paiements.

Exemple travaillé

Sharma General Store veut un code de comptoir unique qui accepte n’importe quel montant. Le propriétaire saisit l’identifiant UPI de la boutique, sharmageneral@okhdfc, et le nom du bénéficiaire Sharma General Store, et laisse le champ Montant vide afin que chaque client saisisse le montant de sa propre facture. Le générateur encode ce lien (les caractères spéciaux sont encodés automatiquement — “@” devient %40 et les espaces deviennent %20) :

upi://pay?pa=sharmageneral%40okhdfc&pn=Sharma%20General%20Store&cu=INR

Il imprime le code et le pose à la caisse. Une cliente le scanne avec son application UPI, voit le nom du bénéficiaire “Sharma General Store”, saisit ₹250 pour ses achats, et paie. Un seul code QR statique gère chaque facture — aucune machine à cartes et aucun maniement d’espèces nécessaire.

Un seul code QR fonctionne-t-il avec toutes les applications UPI ?

Oui. UPI est interopérable, donc ce générateur de code QR UPI universel produit un code standard que BHIM, Google Pay, PhonePe, Paytm et d’autres applications UPI peuvent toutes scanner et payer.

Qu’est-ce qu’un VPA, et est-il requis ?

Un VPA (Virtual Payment Address) est votre identifiant UPI — il ressemble à yourname@okhdfc ou à un identifiant basé sur un numéro de téléphone, et vous le trouverez dans la section profil de votre application UPI. C’est le seul champ obligatoire : sans VPA, il n’y a aucun compte vers lequel le paiement peut aller.

Comment les paiements restent-ils sûrs avec un code QR imprimé ?

Quand un client scanne, son application affiche le nom du bénéficiaire enregistré contre le VPA avant qu’il confirme — demandez-lui de vérifier qu’il correspond au nom de votre boutique. De votre côté, vérifiez toujours le crédit dans votre propre application UPI ou compte bancaire avant de remettre les marchandises ; ne vous fiez jamais à une capture d’écran que le client vous montre.

Un code QR UPI expire-t-il ?

Non. C’est un code statique qui contient le lien de paiement lui-même, sans limite de scans. Il continue de fonctionner tant que le VPA reste actif ; si vous changez votre identifiant UPI, générez et imprimez un nouveau code.
